## 2. `rental_movimientos` tipo="comision" — commissions are COMPLETELY MISSING, not just un-surfaced
There are **only 2** `tipo:"comision"` documents in the entire production DB, and **both belong to a different property** `eb1ea3bcaba94031bf64f82562a7ce80` ("Cata Varela", "Comisión 12.0%"). **ZERO** commission movements exist for any of the 5 properties above. Crucially, these 2 existing movements **prove the generation mechanism works** when a commission % is configured (the "Cata Varela" property has 12%). This isolates the cause to the missing `comisionPct`/`comisionMinima` on the 5 properties.

## 3. Root cause confirmed (code read from deployed source)
`backend/routes_rentals.py` `_gen_comision(rid, r)` (lines 544–561):
```python
pct    = float(prop.get("comisionPct") or 0)
minima = float(prop.get("comisionMinima") or 0)
base   = float(r.get("montoEstimado") or 0)
com    = max(round(base * pct / 100), minima)
if com > 0:
    await _movs().insert_one({... "tipo": "comision" ...})
```
With `pct=0` and `minima=0`, `com=0`, so **nothing is inserted** — silently, by design, no error. The commission is computed off `montoEstimado` at confirmation time and does **not** depend on payment being settled — so your expectation ("comisión a cobrar even before full payment") is already how the code behaves **once a % is set**. The only gap is that the % was never set on these properties.

## 4. Stale-build check — PARTIALLY STALE
Inspected the active run's deployed source (/app/scratch):
- `_gen_comision` **IS present and current** in `routes_rentals.py` (called at line 594 from `create_manual_reservation`, and again around line 631 on the prereserva→confirmada transition).
- `comisionesFaltantes` is **NOT present anywhere in the deployed backend** (`grep` over `backend/*.py` returned nothing). `routes_contabilidad.py` `/resumen` (line 432) only **sums existing** `comision` movements within the date window — it has no "missing / receivable" computation.

**Conclusion:** production is running `_gen_comision` at current logic, but it is **stale with respect to the `comisionesFaltantes` feature** — that field has not been deployed. If it exists in your preview repo, it will only reach production on the next redeploy.

## Recommended remediation
1. **Set the commission %** on the 5 properties (Alquileres → cada propiedad → editar → % de comisión). This is the root fix and makes all *future* confirmations generate commissions correctly.
2. **Backfill the 6 existing reservations.** Setting the % will **not** retroactively create their movements: `_gen_comision` runs only at manual creation / status transition and is guarded by an idempotency check (`exists = find_one({reservaId, tipo:"comision"})`). The 6 already-confirmed reservations need either (a) manual `rental_movimientos` inserts via DB Manager, or (b) a one-off backfill routine. Commission amount = `max(round(montoEstimado * pct/100), comisionMinima)` using each reservation's `montoEstimado`.
3. **Decide + deploy the `comisionesFaltantes` feature** (E1): if "commissions receivable" surfacing is wanted in `/contabilidad/resumen`, that code isn't in production — redeploy to ship it. Optionally reconsider whether confirming a property with no commission configured should warn the user, since the current silent `com=0` skip is what hid this.
