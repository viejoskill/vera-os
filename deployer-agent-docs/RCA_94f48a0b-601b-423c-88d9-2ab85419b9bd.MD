## Why preview looked fine but prod doesn't
In preview the testing agent's rental records were geocoded (had lat/lng), so the map rendered with pins. The real 23 production records were entered/migrated with a street address (`direccion`) but were never geocoded to lat/lng. With no coordinates, the detail-page map and the listing map-toggle have nothing to render — which presents to the user as "the map doesn't appear."

Note: addresses ARE entered (`direccion` is populated), so this is specifically a **missing geocode step**, not "admin hasn't entered addresses."

## Precise fixes (pick based on how geocoding is meant to work in your app)
1. **Data (operational):** Populate lat/lng on the 23 prod `rental_properties`. If your app geocodes on property save, re-save each property so the geocoder runs; otherwise backfill coordinates for the existing records. The map will render pins as soon as any record has non-null lat/lng.
2. **Code (verify — not a confirmed bug):** Check in `routes_rentals.py` whether geocoding (`direccion` → lat/lng) runs automatically on create/update. If it does, these 23 records predate it and need a one-time backfill; if it doesn't, add it so future addresses geocode. I did NOT reproduce this in a sandbox because it requires the live DB + Google geocoding API (no secrets in the sandbox) — treat as a diagnosis to confirm against source, not a verified code fix.
3. Optional UX: if `ReservarPublico.tsx` / `ListingsMap.tsx` hide the map entirely when coordinates are absent, consider an explicit empty-state so "no geocoded data" doesn't look like a broken feature.
